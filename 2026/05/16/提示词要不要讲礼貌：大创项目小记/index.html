提示词要不要讲礼貌：大创项目小记

2026/5/16 项目记录 大创项目 大语言模型 提示词工程

最近终于把这个大创项目推进到可以好好回顾的节点了。

项目题目叫《提示词的礼貌程度对国产大语言模型输出结果的影响分析》。听起来很正经，换成日常一点的说法就是：

和模型好好说话，它会不会更认真答题？

这是西北工业大学大学生创新训练计划项目，我作为项目负责人，和团队成员在指导老师带领下一起推进。中间有选题、数据集、实验、论文、答辩和展示，一路下来比一开始想象的要扎实得多。这里就不写成正式汇报了，简单记一下这个项目是怎么搭起来的。

为什么会做这个

这个题最开始吸引人的地方，是它很日常。

平时用大模型的时候，经常会看到一种说法：跟模型客气一点，它是不是会表现更好？也有人觉得这只是使用者自己的心理安慰。这个问题听起来有点玄，但老师带着我们讨论以后，发现它其实可以被拆得很清楚：

同一道题，只改提示词的语气，模型的正确率、输出长度、推理过程、回答结构会不会变？

于是项目就从这个问题出发，慢慢变成了一套完整实验。

真正做起来以后，我最大的感受是：问模型问题并不难，难的是把题目、prompt、实验记录、清洗脚本、分析口径都整理到能复现、能解释、能写进论文的状态。实验本身像一条线，数据清理和口径统一更像一团线，稍不注意就会绕在一起。

数据集是怎么收拾出来的

现在项目主线用的是 Version 2 数据集。范围收得比较干净：

  • 2023 到 2025 年浙江卷
  • 1 月和 6 月两个场次
  • 九门学科
  • 只保留能完整文本化、没有图片依赖的选择题

最开始抽出来的文本候选题有 644 道，但这只是“抽取阶段”的口径。后来又做了一轮更保守的 LaTeX 转写和人工复核，把公式、图式依赖比较强的题剔掉，最后正式实验使用的是 635 道题。

这个地方后来专门统一了一遍 README。因为如果不说明清楚，后面写论文、做答辩、看图表的时候很容易把 644 和 635 反复混用。现在正式口径已经统一成：

  • 正式题目：635 道
  • 五档语气 prompt：3175 条，也就是 635 × 5
  • 每题每语气重复：3 次
  • 模型：Deepseek、Doubao、Qwen
  • 三模型总记录：28575 条

看到这里的时候我也有点感慨：一开始只是想研究一句“你礼貌吗”，最后变成了快三万条记录的工程活。

prompt 怎么设计

语气不是我们随手编的。项目参考了论文《Should We Respect LLMs? A Cross-Lingual Study on the Influence of Prompt Politeness on LLM Performance》里中文 C-Eval prompt 的礼貌等级，把它映射成五档：

  • VeryPolite
  • Polite
  • Neutral
  • Rude
  • VeryRude

为了减少干扰，每个 prompt 除了语气不同，题目内容和答案格式都尽量保持一致。模型最后需要输出类似 答案：A 的格式，这样后面脚本才能稳定提取选项。

这里也遇到过一点小问题。早期版本里有一些“模拟用户猜测”的设定，后来觉得这会引入额外变量，就删掉了。这个项目越往后做，越觉得控制变量真的很重要。不然最后分析出来的东西看起来很热闹，但你不知道它到底是语气导致的，还是其他细节带出来的。

实验是怎么跑起来的

正式实验分成三个模型目录跑：

  • Deepseek
  • Doubao
  • Qwen

每个模型都用同一套 prompt 文件，同一套重复次数，同一套清洗和分析脚本。运行器主要负责几件事：

  • 按 prompt 调 API
  • 并发请求
  • 断点续跑
  • 保存原始 response
  • 清洗出标准答案
  • 标记异常和重复记录

这一步最像“搭流水线”。单次实验不难，难的是跑到一半不能随便中断；即使中断，也要能接着跑，结果文件还不能乱。

后来我们把原始结果和清洗结果分开存：原始 responses.jsonl / responses.csv 用来追溯，清洗后的 responses_cleaned.csv 用来正式统计。GitHub 对大文件也不太友好，所以又做了压缩清单和 .gz 提交策略。这部分不太浪漫，但很实用：尽量别让仓库被大文件拖慢。

分析的时候发现了什么

最开始我以为重点会是正确率。

结果跑完以后发现，事情没那么戏剧化。整体正确率非常高，三模型都在 98% 以上，而且五档语气之间没有出现那种“越礼貌越准”或者“越粗鲁越准”的稳定规律。

比如总体上：

  • Deepseek 正确率约 98.68%
  • Doubao 正确率约 98.98%
  • Qwen 正确率约 98.79%

如果只看最终对错，这个项目可能会变成一句很干的结论：语气对正确率影响不明显。

但好玩的地方在后面。

语气对 token 成本、输出长度和回答结构的影响更明显。也就是说，模型不一定因为你更礼貌就“答对更多”，但它可能会因为语气不同，换一种方式思考，或者至少换一种方式把答案写出来。

比如：

  • Deepseek 和 Qwen 的变化更多藏在 reasoning_text 里
  • Doubao 的变化更多直接写在 response_text 里
  • Polite 不一定让答案暴涨，但更容易保留正式推理和选项分析这些中段结构
  • 极端语气有时会把回答拉向复述、检查，或者干脆更短的答案格式

这个结论比“礼貌让模型更聪明”要朴素一点，但我觉得更真实。

从实验到论文、答辩和展示

项目中间其实经历了好几轮“看起来差不多了，但其实还不太行”的阶段。

一开始图很多，文字也有点像报告堆出来的。后来就开始慢慢收拾：

  • 先把数据口径统一
  • 再把图表按准确率、token 成本、回答结构分开
  • 然后把论文第 4 部分重新组织成更清楚的讨论
  • 最后再反复改图题、改段落、改那些读起来很“AI 腔”的句子

印象比较深的是回答结构那一块。最早我也差点把它写成“逐格念数值”，后来发现这真的很难读，于是改成看模式：先看 Polite 一列，再看正式推理和选项分析这些关键行，最后对比粗鲁语气有没有把结构带乱。

这一步改完之后，文章终于不像在念表格了。

还有一个小插曲是 Word 版。LaTeX 论文弄完以后，还要转成更接近老师模板的 Word。PDF 转 Word 当然不会完全听话，于是又调首页、页脚、字体、引用上标。属于科研之外的另一项细活。

现在这个项目大概长什么样

目前仓库里比较重要的目录是：

Datasets/Version 2/
Experiments/第二轮正式实验/
Data Analysis/
Codes/
References/

Datasets/Version 2/ 放题库和 prompt。

Experiments/第二轮正式实验/ 放三模型实验结果和主分析。

Data Analysis/ 放更适合论文、答辩和展示材料使用的补充图表和结论。

Codes/ 里则是数据构建、实验运行、清洗、统计分析和出图脚本。

如果以后要回头复盘这个项目，我觉得最重要的不是先看某一张图，而是先看口径：到底用了哪些题、哪些语气、哪些模型、哪些记录。这个东西只要乱一次，后面所有图都会开始变得可疑。

一点点收尾想法

这个项目给我的感觉挺奇妙的。

它一开始是个很日常的问题：和模型说话要不要客气一点？

但做着做着，它变成了一个关于数据清洗、实验复现、统计口径、论文表达和工程整理的综合练习。最后得到的答案也没那么戏剧化：礼貌不是魔法，粗鲁也不是捷径。模型确实会被语气影响，但影响更多体现在它怎么组织回答、怎么分配 token、怎么呈现推理，而不是简单地让正确率明显升高。

这反而让我觉得这个项目更有意思。

毕竟，很多时候真正值得看的，不是“答案有没有变”，而是“它为什么用这种方式给出答案”。

那么，这个大创项目也算是阶段性收尾啦。

论文、答辩和展示都已经做完了，后面就剩下把仓库、材料和这篇小记慢慢归档好。至少现在回头看，它已经从“一个想法”变成了一套能讲清楚的东西。一起加油！~
