数模A题小记：把校园圈项目先跑起来！

2026/5/16 项目记录 项目记录 数学建模 社交网络

是一些关于这次数学建模 A 题的小记啊……

先说说这个题

这次是 5 月 1 号我们学校办的 2026“工大出版社杯”西北工业大学大学生数学建模竞赛。

我和两位队友一起做了 A 题，成员就不展开写真名了，反正就是我们三个人。

文件夹里有 A、B 两题。B 题是农作物优化种植，听起来就是那种“变量一列，约束一堆，然后开始求最大收益”的重量级选手。A 题叫《校园社交平台“好友关系与社交价值”分析》，看起来稍微亲切一点：好友关系、用户属性、发帖互动、话题参与度……总之是一个校园社交网络。

所以最后还是选了 A 题。

我们三个人里，我负责把这篇小记顺手记下来，另外两位队友一起把模型和结果跑了起来。

主要是它比较像能讲人话的题。节点是学生，边是好友关系，再把年级、专业、班级、社团和活跃时段这些信息挂上去，就可以开始研究“圈子”“推荐”“传播”这些东西。至少比一上来就被 10 年种植规划创飞要温柔一点（一点点）。

题目大概分成这几件事：

  • 找社群，尤其是内部连接密度最高的 5 个社群。
  • 给 S11 推荐 3 个还不是好友但适合认识的人。
  • 找科技类话题的关键传播用户，并模拟 48 小时内的扩散。
  • 选做题是文化类话题的定向推送策略。

看起来很清楚，对吧。

然后真正打开附件的时候，事情就开始变成“嗯，我先把项目目录搭好吧”（

数据长什么样

A 题附件是一个 Excel，里面有三张表：

  • 好友关系表
  • 用户属性表
  • 行为数据表

扫完以后发现规模还挺适合做比赛题：

  • 用户节点：200
  • 好友关系：1198
  • 网络密度：约 0.0602
  • 平均度：约 11.98
  • 平均聚类系数：约 0.1869
  • 整张网络是连通的，没有孤立点

用户属性里有年级、专业类别、具体专业、社团和班级。行为表里有动态发布数量、互动频率、活动参与次数、科技类/文化类话题参与度，还有活跃时段。

这就比单纯一张好友表好玩多了。

如果只看谁朋友多，就很容易写成“度数高，所以重要”。但题目明显不是只想要这个。它更像是在问：这个校园圈里，哪些人天然形成了小团体，哪些人适合被系统推到一起，哪些人发一条科技类消息更容易传开。

先把目录收拾出来

我这次先把分析和论文分开了。

本地大概拆成两个工作区：

a-topic-workspace/
math-modeling-a-paper/

这样做有一个很朴素的好处：脚本归脚本，论文归论文，不至于所有东西塞在一起，最后变成“谁动了我的论文主文件”和“这个 csv 到底是哪一问的输出”大型悬疑现场。

a-topic-workspace 里面主要有这些：

scripts/
outputs/
notes/
requirements.txt
run_all_prechecks.ps1
README.md

scripts 负责跑模型，outputs 负责放结果，notes 放一些队内说明。

依赖也尽量收得比较干净：

openpyxl
networkx
pandas
numpy
matplotlib
seaborn
python-louvain

一开始最怕的不是模型不高级，而是大家电脑上跑不起来。所以先把工作区弄成一个“至少能开工”的形状，这件事真的很重要。

一键预检查，先跑通再说

开工清单里写得最实用的一步是：

powershell -ExecutionPolicy Bypass -File .\run_all_prechecks.ps1

它会按顺序跑几个 starter 脚本：

python .\scripts\01_data_overview.py
python .\scripts\02_question1_community.py
python .\scripts\03_question2_recommendation.py
python .\scripts\04_question3_seed_ranking.py

跑完以后，至少要看到这些东西：

outputs\overview\network_summary.json
outputs\question1\community_summary.csv
outputs\question2\s11_candidates.csv
outputs\question3\tech_seed_ranking.csv

看到这些文件真的有一种“终于不是空文件夹了”的安心感。

数模最吓人的时刻，不一定是公式不会推，而是三个人看着题面发呆：你问我从哪开始，我问你从哪开始，最后大家一起沉默。

所以先跑通，哪怕结果还粗糙，也比脑内建模强太多了。

第一问：校园圈里到底有几个圈

第一问做的是社群识别。

主方法用了 Louvain。如果电脑上没有 python-louvain，脚本会退回 networkx 里的 greedy modularity。这个兜底很有必要，不然比赛时换一台电脑就寄，真的会让人很崩溃。

目前跑出来：

  • Louvain 社群数：10
  • 模块度：约 0.2472
  • 内部密度最高的前 5 个社群，分别呈现出一些计算机科学、化学、法学、机械工程、生物学等专业或社团倾向

这里不只是把每个人分到某个编号里，还整理了社群规模、内部边数、内部密度、外部连接比例、年级分布、专业分布、社团分布等。

后来还补了几张图，比如度分布、社群网络图、前五社群密度图、社群关系热力图、功能重叠热力图。

图一出来，论文就好写很多。毕竟“请看图”有时候比“我给你念一串数字”友好得多。

第二问：给 S11 找朋友

第二问是给 S11 推荐 3 个还不是好友的人。

这问做起来还挺像平台推荐系统的简化版。先排除已经是好友的人，再给剩下的候选人打分。

打分里用了这些东西：

  • 共同好友数
  • Jaccard 系数
  • Adamic-Adar 指标
  • 同年级、同专业、同班级
  • 共同社团
  • 活跃时段是否一致
  • 话题参与度相似程度

当前推荐前三是：

S2
S3
S9

比较有意思的是，这三个候选人不是单靠“属性很像”冲上来的，而是和 S11 有比较多共同邻居。也就是说，他们可能早就在同一个社交半径里绕来绕去了，只是好友关系还没有连上。

这就很适合写推荐理由：不是系统硬塞一个陌生人，而是把“你们其实已经离得很近”这件事说出来。

第三问：科技类消息该让谁先发

第三问是信息传播。

现在已经先做了关键用户排序：把网络中心性和行为特征揉在一起，算一个适合科技类话题传播的种子分数。

用到的指标有：

  • 度中心性
  • 介数中心性
  • 接近中心性
  • k-core
  • 平均互动频率
  • 发帖数量
  • 科技类话题参与度

目前排在前面的用户是：

S6
S14
S3
S7
S45

其中 S6 当前综合分最高。

不过这问还没有完全收口。题目要求的是中午 12 点发帖后 48 小时内的传播过程，所以后面还要把传播仿真补上，不能只停在“谁看起来比较重要”。

这也是之后论文里最需要继续补强的部分。

论文工程也搭了一份

论文这边用了 LaTeX，主文件单独放，正文分在 sections 里：

01-problem-restatement.tex
02-problem-analysis.tex
03-assumptions-symbols.tex
04-data-preprocessing.tex
05-question1.tex
06-question2.tex
07-question3.tex
08-question4.tex
08-validation.tex
09-conclusion.tex

编译也写成了一句：

powershell -ExecutionPolicy Bypass -File .\build.ps1

这次比赛没有看到特别强制的官方 LaTeX 模板，所以用 ctexart 先稳稳写起来。模板太重反而容易把时间吃掉，最后变成“题没做完，格式倒是很学位论文”。

三个人分工也简单粗暴：

  • 1 号看数据概览和第一问；
  • 2 号看第二问和第三问；
  • 3 号看论文主文件，把结果、表格和图接进去。

没有什么高深管理学，就是让每个人知道自己先点哪个文件。

几个小坑

第一个坑是中文路径。

平时看着好好的，一到脚本或命令行里就可能开始变成问号。所以最后原始文件夹保留中文，分析工作区尽量叫 a-topic-workspace。朴素，但是省心。

第二个坑是依赖。

Louvain 好用，但不是每台电脑都有。所以第一问脚本加了回退方案。能用 Louvain 就用 Louvain，不能用就先 greedy modularity 顶上。比赛里先活下来，再谈优雅。

第三个坑是论文回填。

脚本跑出结果是一回事，把结果写进论文又是另一回事。outputs 里有 JSON、CSV、图，但论文里还要解释它们：为什么这么建模，结果说明了什么，哪里可靠，哪里还需要验证。

这个步骤看起来像“整理”，其实很花时间。

目前到哪了

现在这个项目已经不是空架子了。

分析工作区能跑，论文工程能编译，第一问的社群结果和图比较完整，第二问已经有 S11 的前三推荐，第三问也有科技类关键用户的初筛。

后面还要补的主要是：

  • 第二问、第三问正文再写厚一点；
  • 第三问传播仿真继续补；
  • 把结果图表和论文里的解释统一起来；
  • 最后检查 LaTeX 的版式和告警。

总之，从“我该从哪里开始啊”进化到了“这几块还要继续补”。虽然听起来还是要干活，但至少已经能看见路了。

这次搭项目最大的感觉是：数模比赛真的不只是建模。

它还包括读题、清数据、搭目录、写脚本、分工、跑结果、画图、写论文、改格式……每一步都不算惊天动地，但每一步漏掉都可能在最后狠狠咬你一口。

不过，把这些东西一点点收拾起来以后，原本很吓人的题目也会慢慢变成一个能推进的工程。

那么这篇就先记到这里啦。

希望后面第三问传播仿真和论文终稿也能顺利收掉。阿猹继续加油！😎
