让Tinyhttpd跑起我的个人博客

2026/5/16 项目记录 项目记录 Tinyhttpd C语言 个人博客

这篇算是给 2025 年寒假专业实践作业补档。

当时作业题目大概是把 Tinyhttpd、SDS 和线程池揉在一起，做一个更能扛事儿的小 Web 服务器。听起来很“专业实践”，实际做着做着，我就开始想：那不如让它把我的个人博客跑起来吧。

于是阿猹的小窝就这样被一个 C 语言小服务器从硬盘角落里拽出来了（？）

一开始我对 Tinyhttpd 的印象其实很朴素：它小，代码不算长，适合看清楚一个 HTTP 服务器大概怎么从 socket、bind、listen、accept 一路走到 send。

但它也确实很“教学”。

比如请求行用固定缓冲区接，静态文件发送方式也偏文本，遇到图片、CSS、JS、中文路径这些现实世界的小东西，就容易露出一点旧时代的味道。要是只跑原来的 demo 页面，那当然没啥问题；但我偏偏想塞进去一个 Hexo 博客。于是事情就变得有意思起来了。

先把项目跑起来倒是不难。在 Tinyhttpd-master 目录下：

make
./httpd

然后它会在 4000 端口等着。浏览器打开 http://127.0.0.1:4000/，如果顺利的话，就能看到博客首页。

第一次看到页面真的出来的时候，我还是挺开心的。虽然它只是本地跑起来，但那种感觉很像：啊，这个小东西终于不是报告里的截图了，它真的在干活。

接下来就是一点点收拾它。

原版读请求的地方，我换成了 SDS。SDS 是 Redis 里面那套动态字符串思路，重点就是不用被固定长度的数组框死。URL 稍微长一点、请求行稍微复杂一点，也不用一直担心它把缓冲区挤爆。

并发那边，我把“来一个连接就开一个线程”的方式换成了线程池。主线程继续接连接，接到之后把活丢给工作线程处理。这样结构会舒服很多，也不用每次请求都现开线程，多少有点省心。

真正让博客能正常显示的，是后面那堆看起来不太起眼的小修小补：

  • URL 解码，不然中文路径会很尴尬；
  • 用 fread + send 发文件，不再拿文本方式硬读静态资源；
  • 补 MIME 类型，让 CSS、JS、PNG、JPG、SVG、ICO 这些都能被浏览器认出来；
  • 把 htdocs 换成真实博客页面，而不是只放一个孤零零的测试页。

这些东西单独看都不算很宏大，但少一个页面就可能怪一下。CSS 没加载，页面就素面朝天；图片没发对，就碎给你看；中文路径没处理好，博客文章就开始失踪。Web 开发有时候就是这样，问题不一定很大，但很会烦人。

中间也踩过一些很典型的坑。

比如 SDS 那边有一次宏名写岔了，SDS_HDR 和 SDS_HDR_VAR 看着很像，编译器可不会心软。还有线程池传 socket 的时候，一开始把 &client_sock 传进去了，结果并发一上来，几个任务抢着看同一个变量，最后就开始出现 Bad file descriptor。

这个 bug 当时很有迷惑性，因为低压下看着还行，一上压测就开始露馅。后来改成按值传 socket，世界安静了。属于是 C 语言很经典的“你以为你传的是一个数字，其实你递过去的是一颗小地雷”（bushi）

压测结果也还挺争气。

在 ab -n 2000 -c 1000 -k 这组测试里，原版大概是 2298.44 RPS，改完之后到了 9917.29 RPS。最长请求时间也从 510 ms 降到了 38 ms 左右。

后面又单独跑了更长一点的压力测试，改造版能到 13325.78 RPS。把个人博客首页放进去测的时候，也跑到了 13701.91 RPS，失败请求是 0。

当然，这不代表它突然变成了什么生产级服务器。它没有 HTTPS，没有 epoll，也还有很多可以继续优化的地方。只是作为一个寒假专业实践作业，它已经从“教材里的小例子”变成了一个能把我博客跑起来的小项目，这一点就已经很够了。

更神奇的是，这个项目最后还真的一路进了答辩决赛。

最后成绩是第三名，奖金 5000 元。

说实话，拿到这个结果的时候还是有点恍惚的。毕竟一开始只是寒假作业，后来变成了查资料、改代码、写报告、做 PPT、准备答辩，最后居然还变成了阿猹人生第一桶金。这个剧情发展多少有点超出预期。

所以这篇就当作一次补档吧。

Tinyhttpd 本身很小，但它刚好把很多东西串了起来：C 语言、网络编程、线程池、字符串处理、静态资源、压测，还有我那个差点继续在角落里吃灰的个人博客。

不管怎么说，它确实跑起来了。

那么，就先记录到这里吧。一起加油！
